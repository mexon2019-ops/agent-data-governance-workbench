## 1. 部署前批准
- [ ] 服务器已由IT批准，系统补丁和访问控制符合内部要求
- [ ] Docker Engine、Compose V2版本已记录
- [ ] 至少10GiB可用空间；建议4核、8GiB RAM、100GiB磁盘
- [ ] 默认端口仅绑定127.0.0.1；通过批准的反向代理/ACL提供访问，不直接暴露公网
- [ ] 反向代理/TLS方案已评估，API文档访问范围受限
- [ ] .env使用独立强密码、AUTH_SECRET，权限600；未提交Git
- [ ] 外部LLM关闭；如需启用另行审批
- [ ] 数据源使用专用只读账号；测试连接前确认授权范围
- [ ] 备份路径及恢复责任人已确认

## 2. 部署执行
建议按以下顺序执行并保存命令结果（勿保存密码或敏感日志）：
```bash

bash scripts/preflight-preview.sh
bash scripts/deploy-preview.sh
bash scripts/health-check.sh
docker compose ps
```
- [ ] Preflight无失败项

- [ ] 下一阶段上线或扩大试用需重新审批

## 6. 故障停止/回退原则
- 出现未授权访问、源库写入、数据外泄疑虑、凭据泄漏或不明数据变更：立即停止试用，隔离访问，保留必要审计证据并按企业事件流程升级。
- 常规容器异常：先记录状态与受控诊断摘要，避免盲目删除数据卷。
- 回退前确认备份可用、变更范围和负责人；不得使用 `docker compose down -v` 清除数据。
- 不在未经评估的情况下回滚数据库迁移或覆盖数据。
