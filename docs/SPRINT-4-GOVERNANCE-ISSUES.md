# Sprint 4：治理问题与整改闭环

## 目标

将数据质量检测发现的异常转为可分派、可跟踪、可复测、可关闭的治理问题，形成责任到部门、责任到人的整改闭环。

## 状态流转

`待分派 → 整改中 → 待复测 → 待关闭 → 已关闭`

- 待分派：质量异常已登记，等待分配责任部门和责任人。
- 整改中：责任人已接收，正在处理。
- 待复测：责任人提交整改说明，等待重新执行原质量规则。
- 待关闭：复测成功且异常记录数为 0，等待治理负责人确认。
- 已关闭：通过系统校验后关闭。

复测未通过时，问题回到“整改中”；复测执行失败不会被误判为通过。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/v1/issues | 问题列表，支持 keyword、status、owner_department |
| POST | /api/v1/issues | 从存在异常的质量检测记录创建问题 |
| GET | /api/v1/issues/{id} | 问题详情及原始检测/最近复测摘要 |
| PATCH | /api/v1/issues/{id}/assign | 分派责任部门、责任人和期限 |
| PATCH | /api/v1/issues/{id}/remediation | 提交整改措施与完成说明 |
| POST | /api/v1/issues/{id}/recheck | 重新执行关联质量规则 |
| POST | /api/v1/issues/{id}/close | 复测异常数为 0 后关闭 |

## 关闭条件

系统不只检查规则的“通过率阈值”，而是要求最近一次复测：
- 执行状态为成功；
- 异常记录数严格等于 0；
- 问题当前状态为“待关闭”。

每一条质量检测记录最多创建一个治理问题，避免重复派单。

## 当前边界

- 当前问题从质量检测运行结果手工生成；后续可增加按严重级别、异常量和阈值自动生成问题。
- 当前使用页面操作完成责任分派和整改说明；后续接入企业消息通知和审批。
- 当前复测同步执行；大表和批量任务需要异步队列及运行资源限制。
