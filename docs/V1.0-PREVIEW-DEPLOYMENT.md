# V1.0-Preview 内网部署手册

## 适用范围
Linux 内网服务器；Docker Engine 与 Docker Compose V2。部署工作台、PostgreSQL及可选隔离MySQL测试库。

## 1. 前置检查
```bash
docker --version
docker compose version
```
建议服务器至少4核CPU、8GB内存、100GB磁盘（建议16GB内存）。确保服务器可访问Docker镜像仓库或已配置镜像缓存。

## 2. 获取项目
```bash
git clone https://github.com/mexon2019-ops/agent-data-governance-workbench.git
cd agent-data-governance-workbench
```

## 3. 配置环境
```bash
cp .env.example .env
openssl rand -hex 32
```
独立生成并配置以下变量：POSTGRES_PASSWORD、MYSQL_TEST_ROOT_PASSWORD、MYSQL_TEST_READER_PASSWORD、AUTH_SECRET、BOOTSTRAP_ADMIN_PASSWORD。管理员密码至少16字符，AUTH_SECRET至少32字符。请勿将.env提交到Git或共享日志。外部LLM保持关闭（LLM_EXTERNAL_ENABLED=false）。

## 4. 启动
```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100
```
访问前端：http://服务器IP:8080；API：http://服务器IP:8000；API文档：http://服务器IP:8000/docs。部署初期限制防火墙访问范围。建议通过企业反向代理提供HTTPS，并避免将8000端口公开给用户。

## 5. 启动隔离MySQL测试库（可选）
```bash
docker compose --profile mysql-test up -d
docker compose ps
```
测试数据库仅绑定宿主机127.0.0.1:3307。后端Compose网络连接地址为mysql-test:3306。

## 6. 验证
- [ ] 所有容器健康、持续运行
- [ ] 登录正常
- [ ] MySQL测试数据源连接测试
- [ ] 元数据采集与目录搜索
- [ ] 标准关联与质量规则测试
- [ ] 治理任务闭环
- [ ] 权限边界测试
- [ ] 确认源库使用只读账号
- [ ] LLM默认关闭

## 7. 运维
```bash
docker compose ps
docker compose logs -f backend
docker compose logs -f frontend
docker compose logs -f postgres
```
如有异常，保存日志（先检查是否包含敏感信息），记录时间、操作和错误摘要，勿直接上传凭据或业务数据。

## 8. PostgreSQL备份与恢复
备份：
```bash
docker compose exec -T postgres pg_dump -U dg_user -d data_governance > backup.sql
```
恢复演练应在独立环境完成。不要直接覆盖试用实例。恢复示例：
```bash
cat backup.sql | docker compose exec -T postgres psql -U dg_user -d data_governance
```
恢复前确认目标库与数据，以上示例仅用于演练/同库恢复场景；生产恢复应遵循审批与停机计划。

## 9. 停止
```bash
docker compose down
```
该命令保留数据卷。不要使用 `down -v`，除非确认删除全部工作台及测试库数据。
