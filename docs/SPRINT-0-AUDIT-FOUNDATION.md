# Sprint 0：操作审计基础

## 本次范围

本迭代为工作台 API 的写操作建立基础审计记录：

- 记录 `POST`、`PUT`、`PATCH`、`DELETE` 请求。
- 保存请求 ID、操作主体占位值、HTTP 动作、资源路径、状态码和发生时间。
- 响应返回 `X-Request-ID`，便于将用户反馈与服务端日志关联。
- 审计记录不保存请求体、查询参数、数据库密码、令牌或业务数据内容。
- 审计表通过 Alembic revision `0002_audit_logs` 管理。

## 当前边界与后续工作

当前版本尚未接入用户认证，因此 `actor` 固定记录为 `anonymous`。中间件不会信任客户端自行传入的用户身份请求头。后续完成登录与服务端会话/JWT校验后，再由可信认证上下文写入真实用户 ID。

当前只建设审计采集基础，不提供面向普通用户的审计查询 API；审计查询应在 RBAC 权限模型落地后提供，并限制为授权管理员可见。

## 数据库迁移说明

- 新建数据库：执行 `alembic upgrade head`。
- 已经执行过 baseline 的数据库：新增审计表由 `0002_audit_logs` 创建。
- 由于历史 baseline 会动态读取当前 SQLAlchemy metadata，`0002` 对审计表采用存在性检查，兼容 baseline 已创建审计表和旧库 stamp 后尚无审计表两种情况。
- 不得修改已在共享环境执行过的历史 revision；后续结构变化必须新增 revision。

## 验收

CI 应覆盖：
1. 既有元数据采集单元测试。
2. 从空白 SQLite 数据库执行完整 Alembic 迁移。
3. 审计模型记录的持久化测试。

本 PR 的代码和 CI 结果不代表已在企业内网 Docker 环境完成部署或数据库联调。
