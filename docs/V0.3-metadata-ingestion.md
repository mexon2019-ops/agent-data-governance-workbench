# V0.3 元数据采集实施说明

## 1. 本阶段目标

在 V0.2 八个页面和数据源配置能力上，建立可运行的元数据采集闭环：

1. 通过环境变量引用源数据库密码，工作台业务库不保存源库明文密码。
2. 使用只读数据库账号连接 SQL Server、Oracle、MySQL、PostgreSQL。
3. 通过 SQLAlchemy Inspector 读取数据库结构信息：Schema、表/视图、字段、数据类型、可空、默认值、主外键及数据库注释。
4. 将采集结果持久化到工作台 PostgreSQL。
5. 提供元数据目录、表详情、字段详情和采集运行记录 API。
6. 只采集结构元数据，不读取业务表数据行，不将业务数据发送给外部模型。

## 2. 本阶段技术取舍

V0.3 先使用 SQLAlchemy Inspector 构建轻量、可测试的四类关系型数据库采集适配层。原因是它能复用现有 SQLAlchemy 驱动和部署结构，先交付可用的数据资产目录，不把 OpenMetadata 全家桶引入到第一轮部署中。

OpenMetadata 作为后续增强的元数据治理引擎保留。官方连接器覆盖 PostgreSQL、MySQL、Oracle、SQL Server；生产部署建议使用外部数据库、搜索引擎和独立 Ingestion 服务，快速 Docker 部署主要适合验证与试用。集成前应在目标内网环境验证版本、资源、驱动、Oracle service name/SID、SQL Server 多数据库、权限和网络策略。

## 3. 新增数据模型

- metadata_tables：数据源、Schema、表名、表类型、注释、字段数、最近采集时间。
- metadata_columns：字段名、类型、可空、默认值、顺序、注释、主键/外键标记。
- metadata_sync_runs：采集状态、表数、字段数、错误摘要、开始/结束时间。

## 4. 新增 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/v1/metadata/tables | 查询元数据表，可按 source_id、keyword 过滤 |
| GET | /api/v1/metadata/tables/{table_id} | 查询表详情及字段 |
| POST | /api/v1/datasources/{source_id}/sync | 手动触发一次元数据采集 |
| GET | /api/v1/datasources/{source_id}/sync-runs | 查询最近 20 次采集记录 |

## 5. 采集边界与权限

- 源数据库必须使用只读账号，建议仅授予读取系统目录/数据字典的权限。
- 不执行 DDL、DML，不调用业务表 SELECT *，不采集行级数据。
- 系统 Schema 默认排除；业务 Schema 采集失败时记录为失败，不把错误详情中的凭据返回给浏览器。
- 连接超时采用短超时；实际网络连通性、TLS、Oracle service name/SID、SQL Server 实例和驱动依赖仍须在客户内网联调。
- 当前版本没有完整登录、RBAC、审批、审计、密钥托管，不应直接开放到公网或作为生产系统。

## 6. 部署配置

在内网部署时通过受控 .env 或 Docker secrets 注入密码变量，禁止提交真实 .env：

- SQL Server 示例：MES_DB_PASSWORD
- Oracle 示例：ORACLE_DB_PASSWORD
- MySQL 示例：MYSQL_DB_PASSWORD
- PostgreSQL 示例：PG_DB_PASSWORD

数据源记录中的 password_env_key 必须与容器内变量名一致。

## 7. 验收标准

- 前端可以新增四种数据库类型的数据源配置。
- 连接测试成功/失败状态可见。
- 对具备可访问权限的测试库执行采集后，目录展示 Schema、表/视图、字段数量。
- 点击字段详情可以看到字段类型、可空、主键/外键、默认值和注释。
- 同一数据源重复采集时更新现有元数据，不产生重复表记录；已删除的源表会从目录中清理。
- 采集失败有运行记录和可读错误摘要。
- 测试过程不读取业务表数据行。

## 8. 自动化测试

CI 使用独立 SQLite fixture 模拟只读元数据源，验证首次采集、重复采集不产生重复表记录、字段主键识别、源表删除后的目录清理，以及采集运行记录的完成状态。另使用真实 FastAPI 进程验证数据源创建、元数据目录 API 和缺少凭据时的安全失败路径。该测试不替代 SQL Server、Oracle、MySQL、PostgreSQL 真实实例的内网联调。
