# Sprint 1：数据资产目录增强

## 本次交付

本迭代在已有元数据采集目录之上增加独立的企业数据资产对象，不再把“数据资产”仅作为通用治理记录。

### 资产字段

- 资产编码：企业内部稳定唯一编码。
- 资产名称：业务人员可理解的名称。
- 物理映射：可选关联已采集的元数据表；一个物理表当前只允许登记为一个资产。
- 业务域：生产、质量、采购、销售、库存、财务等企业业务域。
- 业务描述：说明业务用途、统计口径和使用边界。
- 责任部门、责任人：明确数据资产的管理责任。
- 敏感级别：未分级、公开、内部、敏感、高度敏感。
- 生命周期：待确认、建设中、已发布、已下线。
- 标签：用于搜索和分类。

## API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | /api/v1/assets | governance:read | 查询资产；支持 keyword、business_domain、owner_department、lifecycle_status 筛选 |
| POST | /api/v1/assets | governance:write | 登记资产 |
| PATCH | /api/v1/assets/{asset_id} | governance:write | 更新业务属性、责任归属、分级和标签 |
| DELETE | /api/v1/assets/{asset_id} | governance:write | 删除资产登记 |

新增 Alembic revision：0004_data_assets。迁移兼容项目现有 baseline 的动态 metadata 建表方式：若 baseline 已创建 data_assets，则 revision 仅补齐缺失索引，避免重复建表。

## 安全与边界

- 资产目录仅存储元数据和业务管理属性，不读取源库业务数据行。
- 物理映射只能指向工作台已采集的元数据表。
- 同一物理表不能重复登记为多个资产。
- 资产变更受 governance:write 权限控制，并进入统一 API 变更审计。
- 敏感级别是治理标记，不代表已完成字段级脱敏或访问控制；生产试点仍需结合源系统权限和数据安全制度。

## 验收

1. 可创建不关联物理表的逻辑资产。
2. 可创建关联元数据表的资产，并返回数据源、Schema、表名。
3. 资产编码唯一；同一元数据表不能重复绑定。
4. 可按关键词、业务域、责任部门、生命周期筛选。
5. 可维护责任部门、责任人、敏感级别、生命周期和标签。
6. 删除资产登记不删除源数据库对象或元数据表。
7. 单元测试覆盖资产创建、查询筛选、更新、删除和输入校验。
