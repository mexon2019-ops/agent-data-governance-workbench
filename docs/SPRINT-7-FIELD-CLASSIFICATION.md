# Sprint 7：元数据字段分类分级

## 目标

在数据资产表级敏感级别之外，补充元数据字段级分类分级。分类建议仅分析字段名称和声明数据类型，不读取源数据库业务数据行。

## 分级口径

| 级别 | 说明 | 示例特征（仅用于规则建议） |
|---|---|---|
| 未分级 | 尚未完成责任人确认 | 未命中内置敏感特征 |
| 公开 | 可公开披露 | 由数据责任人按制度人工确认 |
| 内部 | 企业内部使用 | 普通业务标识、内部状态字段 |
| 敏感 | 可能识别个人或主体、联系方式或账户 | 手机、邮箱、地址、姓名、税务标识 |
| 高度敏感 | 涉及认证凭据、身份或金融账户等高风险字段 | 密码、令牌、身份证号、银行卡号、薪资等 |

规则引擎只给出建议，不自动落级。数据管理员可在元数据字段详情中人工确认或调整级别，并记录分类依据、操作人和时间。

## API

- GET /api/v1/metadata/columns/{column_id}/classification-suggestion：按字段名和数据类型给出规则建议。
- PATCH /api/v1/metadata/columns/{column_id}/classification：保存人工确认的敏感级别和分类依据。
- GET /api/v1/metadata/tables/{table_id}：字段详情返回敏感级别、分类依据、确认人和确认时间。

字段分级写操作要求 governance:write。只读用户可以查看分级结果和使用 Agent，但不能修改分类。

## Agent 集成

Agent 外部模型上下文增加未分级字段数量、敏感/高度敏感字段数量两个聚合指标，不发送字段名称或字段明细。这样 Agent 可以提示分类覆盖率风险，同时继续遵守数据最小化原则。

## 验收边界

- 自动建议基于元数据名称匹配，不扫描业务表行，不代表正式合规结论。
- 生产级分类需要企业数据分类分级制度、业务词典和数据责任人确认。
- 本轮尚未实现字段值动态脱敏、SQL 查询结果脱敏或模型外发审批；敏感数据不得因已分级就自动允许外发。
- 高度敏感字段建议默认禁止外部模型使用；后续需在模型网关实现基于分类级别的强制策略。
