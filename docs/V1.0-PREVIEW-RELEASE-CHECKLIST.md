# V1.0-Preview 内测发布清单

> 发布状态：准备中（不是已正式发布）
> 版本目标：企业内部限定人员试用；先验证核心治理闭环、部署与安全边界。

## 版本范围
- 数据源连接与元数据采集（SQL Server、Oracle、MySQL、PostgreSQL；真实环境兼容性需逐一验证）
- 元数据目录与资产登记
- 数据标准、标准关联及审核
- 数据质量规则、检测结果及治理问题整改闭环
- 分类分级及治理分析/驾驶舱
- Agent治理建议（外部模型可选，外发需明确确认；基础脱敏不等于完整DLP）
- FineReport治理基础入口和只读血缘预览（扩展功能需验证）

## 发布前阻断项（完成后方可对内发布）
- [ ] 主分支CI通过，确认对应commit和运行记录
- [ ] Docker Compose干净环境部署成功
- [ ] 修改所有默认/示例密码；使用强随机 AUTH_SECRET、数据库密码及管理员密码
- [ ] 备份与恢复演练（PostgreSQL工作台数据库）
- [ ] MySQL测试库连接测试、元数据采集与目录检索完成
- [ ] 至少一个治理流程端到端：标准/规则、质量检测、问题登记、整改、复测、关闭
- [ ] RBAC：管理员、治理人员、只读用户权限验证；未授权API访问拒绝
- [ ] 源数据库只读账号验证；确认采集过程不读取业务行、不执行源库写操作
- [ ] 外部LLM默认关闭；如试用启用，按流程确认外发并验证脱敏提示
- [ ] 内网部署网络范围、TLS/反向代理和日志检查
- [ ] 试用人员、数据范围、反馈渠道和退出/回滚方式确定
- [ ] 发布说明、管理员部署手册、试用操作指南完成

## 建议试点
- 仅使用虚构样例数据或经授权、脱敏的数据
- 首批试用：信息部门及1–2个业务数据责任部门
- 试用周期建议：2周
- 试用期间禁止将平台直接连接生产数据库写账号；禁止将真实敏感明细外发到未审批模型

## 验收场景
1. 创建/测试数据源连接并采集元数据。
2. 检索表、字段并登记资产。
3. 创建数据标准并关联字段，完成审核。
4. 创建质量规则并运行；确认结果记录。
5. 将异常创建治理任务，分派责任人，整改后复测并关闭。
6. 查看治理概览、标准覆盖、分类统计、质量分析和趋势。
7. 验证权限边界、审计记录、备份恢复及故障处置。
