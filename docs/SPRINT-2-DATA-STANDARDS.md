# Sprint 2：数据标准与字段落标

## 目标

建立可版本化的数据标准库，明确字段业务含义、类型、长度、必填要求、格式约束和取值范围；将标准版本映射到采集到的物理字段，为后续质量规则执行提供标准依据。

## 核心对象

### 数据标准（DataStandard）
- 标准编码（唯一）
- 标准名称、业务域、适用范围
- 责任部门、责任人
- 状态：草稿、已发布
- 当前编辑版本

### 标准版本（DataStandardVersion）
- 版本号（同一标准内递增）
- 业务定义
- 数据类型、最大长度、是否必填
- 格式规则、取值范围、示例值
- 状态：草稿、已发布、已废止
- 生效时间

已发布版本不直接覆盖。创建新版本后，标准进入草稿状态；发布新版本时，旧的已发布版本转为已废止，历史版本和历史映射保留。

### 物理字段映射（DataStandardMapping）
- 关联标准版本和元数据字段
- 映射状态：待核验、已落标、不符合
- 映射说明
- 映射时间

一个标准版本可以映射多个物理字段；同一个物理字段不能在同一标准版本中重复映射。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/v1/standards | 标准列表；支持 keyword、business_domain、status |
| GET | /api/v1/standards/{id} | 标准详情、历史版本和字段映射 |
| POST | /api/v1/standards | 创建标准并自动生成 V1 草稿 |
| PATCH | /api/v1/standards/{id} | 更新标准名称、业务域、说明和责任归属 |
| POST | /api/v1/standards/{id}/versions | 创建下一草稿版本 |
| POST | /api/v1/standards/{id}/versions/{version_id}/publish | 发布当前版本 |
| POST | /api/v1/standards/{id}/versions/{version_id}/mappings | 将标准版本映射到元数据字段 |

所有写接口要求 governance:write。标准编码唯一，版本号在标准内唯一，映射唯一约束由数据库兜底。

## 当前前端能力

- 标准列表与关键词筛选
- 新建标准，维护字段定义、数据类型、长度、必填、格式规则、取值范围和示例
- 创建下一草稿版本
- 发布当前版本

物理字段映射 API 已具备，后续将补充元数据目录中的“按字段映射标准”交互，以及映射差异核验视图。

## 数据治理边界

- 本迭代只管理标准定义和映射关系，不自动修改源数据库字段。
- 发布标准不代表源系统已完成整改。
- 映射状态由治理人员确认；后续落标检查将基于标准版本执行只读检测。
- 标准版本发布、字段映射和变更操作通过统一 API 审计记录。
