# Sprint 3：数据质量规则与只读检测

## 本次交付

新增数据质量规则模型、检测运行记录、规则配置 API 和只读检测执行器。

### 支持的规则类型

| 规则类型 | 规则含义 | 异常统计 |
|---|---|---|
| completeness | 完整性 | 字段值为 NULL 的记录数 |
| uniqueness | 唯一性 | 参与重复值分组的记录数；NULL 不参与唯一性判断 |
| range | 数值范围 | 非 NULL 且小于 min 或大于 max 的记录数 |
| enum | 枚举值 | 非 NULL 且不在 allowed_values 中的记录数 |

通过率计算：

`通过率 = (总记录数 - 异常记录数) / 总记录数 × 100%`

空表按 100% 通过率处理。规则可设置最低通过率阈值，检测通过与否由通过率是否达到阈值决定。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/v1/quality/rules | 规则列表，支持 keyword、rule_type、enabled |
| POST | /api/v1/quality/rules | 创建规则并校验元数据表/字段归属 |
| PATCH | /api/v1/quality/rules/{id} | 启停规则、调整严重级别和通过率阈值 |
| POST | /api/v1/quality/rules/{id}/run | 执行一次只读检测 |
| GET | /api/v1/quality/rules/{id}/runs | 最近 20 次检测记录 |

写操作均要求 governance:write。

## 安全设计

- 不提供自定义 SQL 输入，不执行用户拼接 SQL。
- 执行器从已采集的元数据表/字段中解析物理对象标识。
- 检测条件通过 SQLAlchemy 表达式构建，配置值使用绑定参数。
- 只执行 SELECT 聚合查询，不执行 INSERT、UPDATE、DELETE、DDL。
- 生产源库必须使用只读账号；工作台不保存源数据库明文密码。
- 检测失败只记录错误类型和通用提示，不向用户回显连接串、密码或原始异常文本。
- 质量规则与检测结果进入工作台数据库；检测不修改源库数据。

## 当前边界

- 当前支持完整性、唯一性、数值范围和枚举值四类规则。
- 完整性当前检测 NULL；空字符串/空白字符规则将在后续按字段类型增强。
- 唯一性按重复组中涉及的记录数统计，NULL 不参与唯一性判断。
- 当前为同步执行，适用于小规模试点；大表需后续引入异步任务、超时、采样/分区策略和资源限额。
- 质量规则执行的数据库账号、网络和数据量必须在内网目标环境联调确认。
